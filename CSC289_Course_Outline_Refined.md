## Course Overview

This capstone course integrates software development skills in a team-based project environment delivered through the **AlgoCratic Futures™** immersive learning framework. Students work in cross-functional teams to design, build, and deploy a production-quality web application while navigating a satirical corporate dystopia that mirrors real-world software development challenges.

### Learning Outcomes

Upon completion of this course, students will be able to:

1. Apply agile/Scrum methodology in a team software development context
2. Collaborate effectively with cross-functional team members (developers, designers, database specialists)
3. Design and implement a multi-tier web application with database backend
4. Conduct meaningful code reviews and respond to peer feedback
5. Deploy and maintain a production application
6. Present technical work to stakeholders through pitch and demo formats
7. Document architecture decisions and technical specifications
8. Demonstrate YELLOW and GREEN clearance competencies through exit tickets

### Clearance Progression

  - Test coverage contribution
  - Code maintainability
- **Sprint execution** (10% - TEAM)

#### YELLOW Exit Ticket Specifications

**Component 1: Technical Debugging Challenge** (Due: Week 10, Friday)
- Instructor provides a broken integration (API call, database query, auth flow)
- Student must diagnose issue, fix it, and document the root cause
- Submission: Fixed code + explanation document (300-500 words)
- Rubric: Problem identification (30%), solution quality (40%), documentation (30%)

**Component 2: Substantive Code Review** (Due: Week 10, Friday)
- Review an assigned peer pull request from another team
- Provide line-by-line feedback with specific suggestions
- Identify at least one security/performance concern
- Submission: GitHub PR review comments (minimum 8 substantive comments)
- Rubric: Code comprehension (25%), feedback quality (40%), professionalism (20%), security awareness (15%)

**Component 3: Architecture Decision Documentation** (Due: Week 10, Friday)
- Write an Architecture Decision Record (ADR) for a key decision in your project
- Explain: Context, Decision, Rationale, Consequences, Alternatives Considered
- Submission: ADR markdown document (500-800 words)
- Rubric: Technical accuracy (30%), clarity (30%), completeness (25%), alternatives analysis (15%)

## Frequently Asked Questions

### Platform Assignment
**Q: How are platforms assigned?**  
**A:** Teams will rank their preferences (Task Manager, E-Commerce, Recommendation Engine, Health Tracker). Instructor assigns based on preferences, team composition, and enrollment balance.

### Database Specialist Integration
**Q: What if there aren't enough DBA students for each team?**  
**A:** Teams may share a database specialist across two teams, or proceed without one (with adjusted expectations for database complexity).

### Design Collaboration
**Q: Is design collaboration required?**  
**A:** Strongly encouraged but not mandatory. Teams without design partners build their own themes or use provided templates.

### Exit Ticket Timing
**Q: When are exit tickets due?**  
**A:** YELLOW tickets due Week 10 Friday. GREEN tickets due Week 14 Friday. Can be submitted earlier.

### Team Conflicts
**Q: What if our team has conflicts?**  
**A:** Refer to team contract dispute resolution. Escalate to instructor if unresolved. Individual contribution grades can be adjusted based on peer evaluations.
