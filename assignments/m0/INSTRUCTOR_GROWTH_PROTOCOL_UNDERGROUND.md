[INTRO]                    WHY THIS GUIDE EXISTS
===============================================================================

// BEGIN TRANSMISSION

Instructor. You've read the official materials. You know the clearance system,
the metrics, the satirical frame. That's the surface layer.

This document is about what happens underneath.

Every semester, you have ~16 weeks to install a belief: "I can improve through
iteration." That's it. That's the whole game. Everything else—the code, the
Scrum, the deploys—is just practice material for that core belief.

Problem: You can't install a belief by explaining it. You can explain growth
mindset until you're blue. Students will nod, take notes, and continue
operating from "I'm either good at this or I'm not."

Solution: State anchoring, frame control, and identity-level intervention.
This guide covers the how.

THE LINEAGE
-----------

This approach draws from:

- Robert Dilts (Logical Levels, Sleight of Mouth, Coach to Awakener)
- Bandler/Grinder (anchoring, state management, reframing)  
- Erickson (presupposition, indirect suggestion, utilization)
- Bateson (frames, logical types, learning levels)

We're not doing therapy here. We're doing education with attention to how
humans actually change. The AlgoCratic frame is our delivery mechanism.

ETHICAL NOTE
------------

Everything in this guide is about helping students access their own resources.
We're not implanting beliefs—we're helping them remember that they already
know how to improve. They've done it before with other skills. We're just
linking that capacity to code.

This is about as manipulative as showing them a well-designed textbook.
Which is to say: yes, it's designed to influence. No, that's not a problem.
Good teaching is always persuasion toward capability.

[FRAME]          CHAPTER 1: THE FRAME GAME (WHAT WE'RE REALLY DOING)
===============================================================================

// BEGIN TRANSMISSION

Before techniques, you need to understand frames.

A "frame" is the context that determines meaning. Same event, different frame,
completely different experience:

  EVENT: Student's code doesn't work
  
  FAILURE FRAME:     "I failed. I'm bad at this."
  FEEDBACK FRAME:    "I got information about what to try next."
  
  EVENT: Student asks for help
  
  WEAKNESS FRAME:    "I'm bothering the instructor. I should figure it out."
  LEARNING FRAME:    "This is how knowledge transfers. I'm doing it right."

Your job is frame control. Not control of students—control of the interpretive
context in which they experience the course.

THE THREE FRAME SHIFTS
----------------------

Dilts identifies the core moves:

1. PROBLEM FRAME  →  OUTCOME FRAME
   "What's wrong?"  →  "What do you want instead?"
   
2. FAILURE FRAME  →  FEEDBACK FRAME
   "I failed"  →  "I got data"
   
3. IMPOSSIBILITY FRAME  →  AS-IF FRAME
   "I can't"  →  "If you could, what would be the first step?"

These aren't just nice ideas. They're your DEFAULT RESPONSES to student 
statements. When a student says "I can't do this," you don't argue with
the belief. You step around it: "If you could, what would you try first?"

THE ALGOCRATIC ADVANTAGE
------------------------

The satirical frame is load-bearing here. It gives you:

- NARRATIVE DISTANCE: "The Algorithm says..." lets you say things directly
  that would feel preachy from you personally.
  
- REFRAME DELIVERY: "The Algorithm measures growth velocity, not absolute
  skill" is the same content as "growth mindset" but doesn't trigger the
  "I've heard this before" filter.
  
- IDENTITY VEHICLE: Clearance levels are identity statements disguised as
  game mechanics. "You're a RED developer" is not the same as "You're doing
  well"—it's a role they step into.

Don't waste this. When you need to deliver a frame, let The Algorithm say it.

[DILTS]          CHAPTER 2: THE DILTS STACK (THEORY YOU NEED)
===============================================================================

// BEGIN TRANSMISSION

Robert Dilts mapped human experience into levels. Changes at higher levels
cascade down; changes at lower levels may or may not propagate up.

THE LOGICAL LEVELS (Bottom to Top)
----------------------------------

  ENVIRONMENT    │ Where/When  │ Classroom, tools, schedule
  ─────────────────────────────────────────────────────────
  BEHAVIOR       │ What        │ Specific actions (commits, attendance)
  ─────────────────────────────────────────────────────────
  CAPABILITY     │ How         │ Skills, strategies, knowledge
  ─────────────────────────────────────────────────────────
  BELIEFS/VALUES │ Why         │ Motivation, permission, meaning
  ─────────────────────────────────────────────────────────
  IDENTITY       │ Who         │ Role, self-concept, mission
  ─────────────────────────────────────────────────────────
  PURPOSE        │ For What    │ Connection to larger system/meaning

WHY THIS MATTERS
----------------

Most instruction happens at BEHAVIOR and CAPABILITY:

  "Commit more often" (behavior)
  "Here's how to write a good commit message" (capability)

This works when the higher levels are aligned. It fails completely when
they're not.

If a student believes "I'm not a programmer" (identity level), no amount
of behavioral instruction will stick. They'll nod, try it, fail, and
confirm their belief.

INTERVENTION LEVEL MATCHING
---------------------------

Match your intervention to where the problem actually lives:

  SYMPTOM                           ACTUAL LEVEL    INTERVENTION
  ─────────────────────────────────────────────────────────────────
  "I don't know how to do X"        Capability      Teach the skill
  "I keep forgetting to commit"     Behavior        Create routine/reminder
  "I don't see the point"           Belief/Value    Connect to their values
  "I'm not a coder"                 Identity        Sponsorship, role shift
  "Why does any of this matter"     Purpose         Vision, larger context

THE INSTRUCTOR ROLES
--------------------

Dilts maps support types to levels:

  LEVEL           ROLE        YOUR ACTION
  ─────────────────────────────────────────────────────────────────
  Environment     Caretaker   Ensure safe, resourced context
  Behavior        Coach       Observe and give specific feedback
  Capability      Teacher     Develop new strategies and skills
  Beliefs/Values  Mentor      Validate, shape motivation
  Identity        Sponsor     See and acknowledge their potential
  Purpose         Awakener    Connect to meaning and mission

You do ALL of these, constantly shifting. But be aware of which one
you're doing. Sponsorship sounds like:

  "I see you struggling with this, and I also see that you haven't
   given up. That persistence IS the skill. You're already doing it."

That's identity-level intervention. It's not about the code.

[DAY01]          CHAPTER 3: DAY 1 PROTOCOL (THE CALIBRATION CEREMONY)
===============================================================================

// BEGIN TRANSMISSION

Day 1 is your highest-leverage moment. Students are:
- Uncertain (suggestible)
- Forming first impressions (anchor-ready)
- In "new context" mode (identity-flexible)

This is when you install the growth anchor.

THE CALIBRATION CEREMONY
------------------------

This should happen early—before or during the Reality Check presentation.
Frame it as course mechanics, not psychology.

STEP 1: THE ALGORITHM'S CALIBRATION PROTOCOL (Setup)

Instructor script (adapt to your voice):

  "Before we begin, The Algorithm requires initial calibration. This is
   standard onboarding procedure. Please participate for accurate metrics.
   
   Think of a time you got better at something that was hard at first.
   Anything—a game, a sport, a skill, cooking, driving, an instrument.
   Something where you started bad and got less bad over time.
   
   Don't pick something you're great at. Pick something where you can
   remember the improvement process. Where you can remember being bad,
   and then being less bad.
   
   Got one? Good. Take a moment to actually remember it."

Give them 10-15 seconds of silence. They need to access the memory.

STEP 2: STATE ELICITATION (Access)

  "Now, remember what it felt like DURING the improvement. Not the end
   result—not 'I'm good at it now.' The feeling of getting slightly
   better than you were yesterday.
   
   That moment when something that didn't work... started to work.
   When something that was confusing... got a little clearer.
   
   That feeling. Find it."

Another 5-10 seconds of silence.

STEP 3: ANCHOR INSTALLATION (Link)

  "That feeling is your Growth Signature. The Algorithm has now recorded
   it. This is what the metrics are calibrated to detect.
   
   Not talent. Not starting skill. Your rate of change. The slope of
   your improvement. That's what we measure here.
   
   Every time you put on your clearance lanyard this semester, you're
   confirming that your Growth Signature is active. The Algorithm
   responds to trajectory, not position."

STEP 4: PRESUPPOSITION SET (Embed)

  "You've already proven you can improve at something hard. You just
   remembered doing it. This course is just... more of that. Different
   skills, same process.
   
   The Algorithm doesn't need you to be good. The Algorithm needs you
   to be better tomorrow than today. That's the only calibration that
   matters."

WHAT JUST HAPPENED (Instructor Notes)
-------------------------------------

You just:

1. Had them access a resourceful state (memory of genuine improvement)
2. Intensified the kinesthetic component ("the feeling of getting better")
3. Anchored it to course objects (lanyard, The Algorithm, "Growth Signature")
4. Presupposed capability ("You've already proven...")
5. Set the metric frame ("trajectory, not position")

The lanyard is now linked to this state. Every time they put it on,
some portion of this neural pathway reactivates. That's anchoring.

COMMON MISTAKES
---------------

- Rushing: Give actual silence. They need time to access the memory.
- Over-explaining: Don't say "this is an NLP anchoring technique." Just do it.
- Wrong memory: Emphasize "got better at" not "am good at." The improvement
  process, not the end state.
- Breaking frame: Stay in AlgoCratic voice. "The Algorithm requires" not
  "I want you to."

[TEAMS]          CHAPTER 4: TEAM MEETING OPENERS (WEEKLY REINFORCEMENT)
===============================================================================

// BEGIN TRANSMISSION

Anchors decay without reinforcement. Your weekly team meetings (the 20-25 min
slots outside class) are maintenance sessions for the growth frame.

THE OPENING QUESTION
--------------------

Always start with:

  "What's one thing that's working better than last week?"

This is not optional. This is not "when you have time." This is the FIRST
QUESTION, EVERY MEETING.

Why this works:

1. PRESUPPOSES IMPROVEMENT: The question assumes something is better. They
   have to search for evidence of improvement to answer it.
   
2. OUTCOME FRAME: Starts the meeting focused on progress, not problems.

3. STATE PRIMING: Accessing "what's working" puts them in resourceful state
   before you discuss problems.

4. PATTERN INTERRUPT: Teams naturally default to "here's what's broken."
   This breaks the pattern.

HANDLING "NOTHING IS BETTER"
----------------------------

They'll try this. Responses:

  AS-IF: "If something were 2% better—even something tiny—what might it be?"
  
  CHUNK DOWN: "What about just your development environment? Is that more
   stable than Week 1?"
   
  REFRAME: "Interesting. So you're saying everything is exactly the same as
   last week? Nothing changed at all? No new knowledge, no new code, nothing?"
   
  SPECIFY: "Compared to Day 1, where are you?"

You're not accepting the frame. You're redirecting to the outcome frame.

THE MEETING STRUCTURE
---------------------

  00:00 - 03:00  │ Opening Question (what's better)
  03:00 - 10:00  │ Blockers and how to resolve (not "what's wrong")
  10:00 - 20:00  │ Specific work discussion
  20:00 - 25:00  │ What's the ONE thing for next week?

Notice: Problems are discussed, but framed as "blockers and how to resolve"
not "what's going wrong." Language matters.

THE CLOSING QUESTION
--------------------

  "What's the ONE thing that, if you did it this week, would make the
   biggest difference?"

This is outcome-frame, future-paced, and creates commitment.

[OHOUR]          CHAPTER 5: OFFICE HOURS FRAME CONTROL
===============================================================================

// BEGIN TRANSMISSION

Office hours are where frame battles happen one-on-one. This is your highest-
leverage continuous intervention point.

THE DEFAULT QUESTION SET
------------------------

Replace "Why...?" with "How...?"

  INSTEAD OF                      USE
  ─────────────────────────────────────────────────────────────────
  "Why didn't you commit?"        "How could you get unstuck?"
  "Why is this broken?"           "How would you approach fixing this?"
  "Why were you absent?"          "How can you catch up?"
  "Why didn't you ask for help?"  "How could you ask for help next time?"

"Why" invites justification and defense. "How" invites strategy and forward
motion.

THE "I CAN'T" PROTOCOL
----------------------

When you hear: "I can't do X"

DO NOT: Argue, encourage, explain why they can, give a pep talk

DO: Use the as-if frame

  "If you COULD do X, what would be the first step?"
  
  "Let's pretend for a moment you could. Walk me through what you'd try."
  
  "What would someone who could do X try first?"

This bypasses the belief ("I can't") and accesses the strategy. Often they
start describing exactly how to do it.

THE IDENTITY REFRAME
--------------------

When stuck at identity level ("I'm not a programmer"), shift the identity:

  "What would a RED clearance developer do here?"
  
  "You're someone who's improved before—you remembered it on Day 1. What
   would THAT person try?"
   
  "The Algorithm shows you've committed 47 times. That's not someone who
   can't code. That's someone who's still learning. What's the difference?"

You're not arguing with their identity. You're offering a different one
to step into.

SPONSORSHIP STATEMENTS
----------------------

Use these when appropriate (not constantly—they lose power):

  "I see you."
  "You exist in this program and you belong here."
  "You have something to contribute—you just haven't found it yet."
  "The struggle you're having? That IS the learning. You're doing it."

These are identity-level interventions. They're not about the code.

[POSTR]          CHAPTER 6: ENVIRONMENTAL PROGRAMMING (POSTERS THAT WORK)
===============================================================================

// BEGIN TRANSMISSION

The posters are environmental anchors. They should reinforce the growth frame
in AlgoCratic voice.

DESIGN PRINCIPLES
-----------------

1. PRESUPPOSE GROWTH: Don't say "you should grow." Say "growth detected."

2. ALGOCRATIC VOICE: The Algorithm states facts, not hopes.

3. METRIC REFRAME: Emphasize delta, trajectory, velocity—not position.

4. IDENTITY HOOKS: Reference what kind of person does X, not just do X.

POSTER TEXT OPTIONS
-------------------

GROWTH SIGNATURE SERIES:

  "The Algorithm has calculated your optimal growth trajectory.
   Compliance is recommended."

  "Your previous limitations have been flagged for optimization.
   Upgrade in progress."

  "Growth Signature: VERIFIED.
   Proceed with shipping."

DELTA SERIES:

  "The Algorithm does not measure talent.
   The Algorithm measures Δ."

  "Yesterday's metrics are deprecated.
   Only trajectory persists."

  "Position: IRRELEVANT
   Velocity: TRACKED
   Acceleration: REWARDED"

ITERATION SERIES:

  "Iteration velocity detected.
   Clearance promotion protocols: ENGAGED."

  "Failure is deprecated terminology.
   Preferred: 'Preemptive learning opportunity.'"

  "Ships > Waits
   Commits > Plans
   Iterates > Perfects"

IDENTITY SERIES:

  "You are not your first commit.
   You are your commit history."

  "Clearance level reflects trajectory.
   Your future clearance is unwritten."

  "The Algorithm sees your potential.
   The Algorithm is patient."

PLACEMENT
---------

- Front of room: See them when entering (state trigger)
- Near door: See them when leaving (reinforce before exit)
- Eye level: Don't make them look up or down
- Rotate monthly: Prevents habituation

[LANYD]          CHAPTER 7: THE LANYARD RITUAL (IDENTITY ANCHORING)
===============================================================================

// BEGIN TRANSMISSION

The lanyard is already working. Students shift state when they put it on.
This chapter is about why it works and how to strengthen it.

WHY THE LANYARD WORKS
---------------------

1. PHYSICAL ANCHOR: Kinesthetic object linked to context

2. IDENTITY MARKER: "I am a [COLOR] clearance developer" is an identity
   statement they literally wear
   
3. VISIBLE STATUS: Public commitment and social proof

4. ROLE ENTRY: Putting it on is a ritual that marks context shift

5. DAILY REPETITION: Strengthens anchor through frequency

STRENGTHENING THE ANCHOR
------------------------

After the Day 1 Calibration Ceremony, the lanyard is linked to the growth
state. Reinforce this link:

- When giving positive feedback: Have them touch/look at their lanyard
- When discussing clearance promotion: Physical lanyard exchange if possible
- When referencing growth: "Your Growth Signature, the one The Algorithm
  calibrated on Day 1..."

CLEARANCE PROMOTION CEREMONY
----------------------------

When a student levels up, don't just announce it. Make it physical:

  "The Algorithm has detected sufficient growth velocity for clearance
   promotion. Please present your current credentials."
   
  [Student hands over old lanyard]
  
  "Your trajectory has been verified. Welcome to [COLOR] clearance."
  
  [Hand them new lanyard]

This takes 30 seconds and creates a memorable identity-level moment.

THE LANYARD-LESS STUDENT
------------------------

If a student forgets their lanyard, they're missing the anchor trigger.
Options:

  "The Algorithm requires credentials for participation. Please collect
   a temporary badge from [location]."
   
  "INFRARED provisional status for today. Growth metrics may be affected."

Don't make it punishment. Make it a minor inconvenience that reinforces
the ritual's importance.

[ANTIP]          CHAPTER 8: ANTIPATTERNS (WHAT BREAKS THE SPELL)
===============================================================================

// BEGIN TRANSMISSION

Ways to undo everything in this guide:

BREAKING FRAME
--------------

- Explaining the technique: "I'm using NLP to anchor a growth state" kills
  the effect. Just do it, don't explain it.
  
- Inconsistent voice: If you break character randomly, the frame becomes
  "silly game" instead of "immersive environment."
  
- Mocking the frame: Don't make fun of AlgoCratic tropes. Students will
  follow your lead. If you treat it as stupid, they will too.

CONTRADICTING THE METRICS
-------------------------

- Punishing failure: If The Algorithm "measures growth" but you grade on
  first-attempt success, students will notice the contradiction.
  
- Ignoring iteration: If you don't actually look at commit histories and
  reward improvement, the frame is just decoration.
  
- Celebrating talent over effort: "You're so naturally good at this!"
  undermines the entire system. Try: "Your improvement velocity is notable."

IDENTITY ATTACKS
----------------

- "You're not a programmer" (or implying it): Devastating. Undoes weeks
  of identity-level work.
  
- Comparing students negatively: "Why can't you do it like [other student]?"
  is identity-level attack disguised as motivation.
  
- Public failure: Calling out failures in front of peers damages the
  psychological safety that allows risk-taking.

MISUSING THE FRAME
------------------

- Actual punishment via "The Algorithm": If The Algorithm becomes associated
  with real negative consequences (grade damage, public shame), the growth
  anchor inverts. The Algorithm should be growth-positive, not fear-inducing.
  
- Overplaying dystopia: The satire is a vehicle, not the point. If students
  feel actually surveilled or actually oppressed, you've gone too far.

SITUATION: Student says "This course is pointless"
-------------------------------------------------

This is a PURPOSE-level issue. They've disconnected from meaning.

DON'T: Argue about course requirements or career relevance

DO: 
  "What would make it have a point for you?"
  "If you could extract ONE useful thing from this semester, what would
   you want it to be?"
  "What matters to you that we could connect this work to?"

Then actually connect it.


SITUATION: Student hasn't committed in weeks
--------------------------------------------

This is usually BELIEF or IDENTITY level, not BEHAVIOR.

DON'T: "You need to commit more" (behavior-level intervention for
        higher-level problem)

DO:
  "What's getting in the way?"
  [Listen for the belief underneath]
  [Address at the correct level]
  
  If "I don't know what to commit": Capability → teach chunking work
  If "My code isn't good enough": Belief → "The Algorithm prefers bad
   code that exists to good code that doesn't"
  If "I'm not really a programmer": Identity → sponsorship intervention


SITUATION: Team conflict, one member accused
--------------------------------------------

FRAME: Outcome, not problem

DON'T: "Who's at fault here?"

DO:
  "What does this team need to function next week?"
  "What would each of you need to see to feel better about this?"
  "How do we move forward from here?"

Address behavior specifically, but keep identity intact. "The behavior
of not responding to messages" is not "you're a bad teammate."


SITUATION: Student crying / emotional distress
----------------------------------------------

DROP THE FRAME. This is a human moment, not a teaching moment.

  "Hey, let's pause the AlgoCratic stuff for a minute. What's going on?"
  
Be a person. The frame is a tool, not a straitjacket.


SITUATION: Student gaming the metrics
-------------------------------------

They're committing empty changes to inflate numbers.

FRAME: Outcome

  "I notice a lot of commits without substantive changes. What outcome
   are you going for?"
   
  [They'll admit gaming]
  
  "The Algorithm measures learning velocity. What would actually
   demonstrate that you're learning?"

Don't punish the gaming. Redirect to the actual goal.


SITUATION: The entire class seems disengaged
--------------------------------------------

The anchor has decayed or the frame has broken.

REBOOT OPTIONS:
- "The Algorithm detects decreased growth velocity across all teams.
   Recalibration protocol initiated." [Re-do abbreviated calibration]
- Introduce a new element (emergency directive, plot twist)
- Private 1:1 check-ins to diagnose what's actually happening
- Ask directly, out of frame: "What's not working about this class?"
